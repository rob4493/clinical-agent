# Legacy private evidence installation

The public checkout contains no protected clinical documents or complete private-runtime claim packages. The fictional synthetic demo and the public evaluation versions of competition Modules 1 and 2 run without private evidence. Neither becomes an authentic approved module. This document describes only the explicit legacy private-source graph and its historical regression fixtures.

The `evaluation/` directory contains separately authored summaries marked reviewedForEvaluation and competitionReady. Default competition mode loads these public packages. They are not substitutes for the publications or private packages required by this legacy installer. Their hashes cover public summary content only. Do not replace private installation pins with those hashes or treat evaluation summaries as authentically approved evidence.

`EvidenceSources.example.json` is the exhaustive expected-file inventory: exact relative filename, module owner, byte size and SHA-256 for each input, plus official source links, document identifiers, package pins and claim IDs. It contains no source passages. Obtain the listed source originals legally from their official organizations. Browser captures may not be byte-reproducible: a fresh download with a different hash must fail verification. Do not modify a pin to accept it. A different edition requires a separately reviewed source/claim migration.

The two unchanged knowledge documents, source-derived appraisals, clinical-review fixtures and complete private package.json manifests must be supplied separately by an authorized project administrator only when their intended use is permitted. The public metadata cannot reconstruct them; this tool deliberately does not scrape publishers, generate claims or regenerate manifests. If rights or exact bytes are unavailable, leave the legacy private graph closed. Public evaluation and synthetic operation remain independent.

Arrange obtained files under the exact relative paths in the inventory inside an ignored local `privateEvidence` staging directory, preserving original bytes. Keep authoritative originals separately from this staging copy. Do not place these files in frontend/public, frontend/src, a web-served directory, an image context, a release archive or Git. The operator should check supplied PDFs for encryption, JavaScript, launch actions and embedded executable attachments before installation; byte verification is not a malware scanner. Limit filesystem access to the runtime account and authorized administrator.

From the project root, using an external NEW directory outside this checkout:

```powershell
.\.venvMilvus\Scripts\python.exe -B -m tools.evidenceInstall install --source .\privateEvidence --destination C:\clinicalPrivateEvidence --confirm-authorized-use
.\.venvMilvus\Scripts\python.exe -B -m tools.evidenceInstall verify --source C:\clinicalPrivateEvidence
.\.venvMilvus\Scripts\python.exe -B -m tools.runDemo --mode competition --private-root C:\clinicalPrivateEvidence
```

The destination example is an operator choice, not a machine-specific application default. Installation rejects in-repository destinations, existing destinations, traversal, symlinks/junctions, missing files, unexpected sizes and mismatched hashes. A failed partial destination is never usable; do not configure the runtime to use it. It must be removed by the administrator before deliberately retrying. The installer never deletes originals. Runtime validators recheck source identities, module ownership and package/claim bindings before use and during analysis. Invalid provenance fails closed without routine partial analysis. Exact hashes bind previously verified identity; installation does not repeat editorial source verification, grant approval or update source status. Installation verifies the complete inventoried fixture set, including the two knowledge documents and historical review inputs, to preserve the existing regression baseline; these administrative files are not themselves clinical approvals.

For a controlled deployment, build/distribute only the audited source-free allowlist. Install evidence separately on a private persistent volume after image construction. Mount the private directory read-only and set `MODULE_ROOT` to `<mount>/backend/app/modules` and `CLINICAL_EVIDENCE_ROOT` to `<mount>`. Never put private files in image layers or build arguments. No Dockerfile/image is provided; .dockerignore excludes everything until a reviewed explicit image allowlist is designed. Do not archive this working directory. Use the source-free export process described in README.

Health, module discovery and readiness do not create network clients. Competition readiness reflects only local offline evaluation dependencies; it does not indicate clinical approval. A missing/altered private installation prevents startup of the explicitly selected private graph; it does not fall back to public evidence. The raw source files have no download route and no static mount. Public APIs retain existing bounded source metadata and original clinical response projections, not file bytes; neither private paths nor entire provider/file payloads may be returned. Avoid reverse-proxy body logging. Pending sources remain pending and all four authentic modules remain inactive.

The runtime account must not have write access to evidence. Hash checks are not distributed locking and cannot defeat an administrator modifying files between checks. Stop servers before maintenance, install a new independently verified volume, switch it deliberately and restart. Roll back code and the matching entire evidence volume together; never mix manifest versions. Shared/public tester hosting still requires authentication, TLS, proxy/header and log review, operational consent and publisher-use clearance. The loopback demo command is not such a deployment.

Full historical evidence regressions require the private fixture files at the original ignored relative paths of a private developer workspace. These remain unchanged; absent protected fixtures are not fabricated or silently skipped. Public source-only checks exercise public evaluation, synthetic operation and installer/fail-closed behavior. A public clone can run both public evaluation modules, but cannot run the private-source historical regressions without their separate fixtures.

## Before any first push

Review every entry in `ReleaseFiles.txt`, the source-distribution exclusions and the scanner report. Do not initialize, stage, commit or push a directory containing additional unreviewed files. If Git is later authorized, stage only that explicit allowlist, compare `git ls-files` and the staged diff against it, and scan every reachable historical object—not only the working tree. Stop for any restricted artifact, credential, patient information, generated case record or real local environment file. A prior commit containing such bytes must never be made safe merely by adding .gitignore. This task did not inspect remote repository history or establish remote visibility; review those separately before pushing or merging any remote history. Never force-push to bypass review.
